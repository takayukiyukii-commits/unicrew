# UNICREW 0.2.50 の新機能

## 🔍 「インストールしたのに認識しない」を根治

UNICREW が CLI を探す場所を全面的に見直しました。

- **起動時に「CLI がよく入る場所」を PATH に足すようにしました**
  macOS で Dock / Finder からアプリを起動すると、OS から渡される PATH が最小限
  （`/usr/bin:/bin` など）になり、`~/.local/bin` の Claude Code も Homebrew も
  npm で入れたコマンドも**見えていませんでした**。インストールは成功するのに
  ずっと「未インストール」と表示される状態です。これを解消しました
- Windows では npm で入れた CLI（`gemini` / `opencode` / `qwen` など）の実体が
  `.cmd` ファイルのため、探索から漏れることがありました。拡張子を正しく展開するようにしました
- pnpm / asdf / mise / fnm / nodenv / Volta / nvm / Linuxbrew 配下も探します

実測：PATH がほぼ空の状態でも、Claude / Codex / Gemini / OpenCode / Qwen / Ollama /
Goose / Kiro / Kimi / codex-acp の**全部を見つけて起動できる**ことを確認しました。

## 🔁 更新で「同じ CLI が2つ」になるのを防止

公式インストーラで入れた Claude Code に対して、更新時に npm 版を重ねてインストールして
しまうことがありました（PATH の順番次第で古い方が動き続けます）。
npm で入れたものだけを npm で更新するようにしました。

## 🩹 失敗しても詰まないように

- Gemini CLI のインストールに失敗したときも、手動コマンド（コピーボタン付き）と
  サポート導線が出るようになりました
- **失敗したあとに「もう一度」が押せるようになりました**（以前はボタンが消えて、
  アプリを再起動するまで再試行できませんでした）
- Node.js が無い PC で Gemini のインストールを押したとき、「インストール中…」のまま
  固まらなくなりました
- Gemini / OSS 系 CLI にも多重起動ガードを入れました（連打してもインストーラは1つだけ）
